# Keep dashboard network responses attached to their selected request

## Problem

Network list and detail requests can complete out of order. A response body from the previously expanded request can appear beneath the newly selected URL. Session and filter changes, collapse, or clearing the list can also leave earlier responses able to update the current panel.

## Changes

Give list and detail requests independent generations, invalidate them when their scope ends, and keep their completion callbacks attached to the active request. Clearing and collapsing also invalidate pending detail reads. Add deferred-response tests for stale completion, cleanup, failure, and independent list/detail requests; run them in the dashboard CI build.
