# Keep the dashboard usable when browser storage is unavailable

Upstream pull request: [#2504](https://github.com/vercel-labs/agent-browser/pull/2504)

Status: open; merged: false.

## Problem

The persisted-activity atom reads localStorage during module initialization, and the persistence toggle writes to it without catching access errors. A browser that denies storage access can therefore prevent the dashboard from loading or interrupt the toggle after its in-memory state changes.

## Changes

Use guarded browser storage helpers for activity preferences and history. The UI can keep its in-memory state when storage is blocked or full. Add tests for denied access, failed operations, server rendering without window, and ordinary storage behavior; run them in the dashboard build.
